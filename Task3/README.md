# Task 3. Data Encryption at Rest & In Transit

## Классификация и защита данных

| Данные | В чём необходимость защиты | Инструменты защиты |
|--------|-----------------------------|---------------------|
| Медицинские данные (анализы, заключения, назначения) | Высокая чувствительность, врачебная тайна, регуляторные требования (152-ФЗ) | Шифрование БД (AES-256, TDE), TLS/mTLS при передаче, контроль доступа (RBAC/ABAC), аудит доступа |
| Персональные данные (ФИО, контакты, документы) | Защита персональных данных, репутационные риски | Шифрование БД, TLS для всех API, псевдонимизация/минимизация данных |
| Платёжные данные (чеки, статусы, токены) | Финансовые риски, требования PCI DSS | Токенизация, TLS/mTLS, шифрование журналов, сегментация платежного контура |
| Данные учёта ТМЦ и бухгалтерии | Коммерческая тайна, финансовая отчётность | Шифрование файлов/бэкапов, TLS к интеграциям (1С, API), контроль доступа |
| Аналитические данные (Data Lake) | Используются для BI, содержат обезличенные наборы | Обезличивание/псевдонимизация, шифрование хранилища (SSE-KMS), TLS к BI-инструментам |
| Логи и аудиторские записи | Трассировка инцидентов, доказательная база | Неизменяемое хранение (WORM), шифрование, централизованный сбор в SIEM |

## Итог
Система защищает данные **в хранении** (Encryption at Rest) и **в передаче** (Encryption in Transit) с помощью шифрования, токенизации, обезличивания и RBAC/ABAC. Для контроля используются аудит, SIEM и WORM-хранилища.
